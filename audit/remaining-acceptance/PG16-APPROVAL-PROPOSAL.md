# PostgreSQL 16 parity proposal — not executed

Inventory found only PostgreSQL 18.6, with no usable PG16 runtime or container daemon. PG18 evidence does not establish PG16 parity. The simplest approval option is a separate local Homebrew PG16 installation and a matching pgvector build. Alternatively, supply an existing PG16 binary directory and compatible vector extension; no package installation is then needed.

Proposed installation, only after explicit authorization:

1. Recheck and freeze the official Homebrew formula/version, bottle checksum and dependency plan. Current formula advertises PostgreSQL16.15; installed Homebrew metadata resolves the arm64 Tahoe bottle and uses openssl@3, while public metadata may differ. Resolve any discrepancy before installation. Install `postgresql@16` with `--force-bottle --skip-post-install --skip-link`, disabling auto-update, dependent upgrades and cleanup for this invocation. Skip-post-install avoids the default persistent database cluster; skip-link avoids normal global-prefix linking, but an `opt/postgresql@16` link and service-definition plist/var-log directory can still be written. A service definition is not a started daemon. Dependency installs do not inherit the two skip options. Stop for an additional decision if the frozen plan requires any new/updated dependency, source build or broader action.
2. Download pinned upstream pgvector v0.8.7 into the owned workspace, compile using `/opt/homebrew/opt/postgresql@16/bin/pg_config`, and install its extension files only into that PG16 installation's reported library/share and server-include `extension/vector` directories. The upstream installation also writes three vector headers; these are included explicitly. Never copy the PG18 extension binary. Do not invoke `sudo`, install developer tools or broaden the dependency plan without identifying the additional requirement.
3. Adapt the existing test runners to accept an explicitly guarded PG16 binary directory, verify SQL server major16 and matching vector extension, and use separate PG16 output directories. Then create only a fresh private Unix-socket fixture with a synthetic role/database under `/tmp`, apply all18 migrations, and rerun native retrieval, strict persistence/revocation/replay and compiled authenticated browser checks. Preserve failures as evidence. Stop and remove the owned fixture afterward. The current PG18-hardcoded runners cannot themselves establish PG16 parity.

The approval scope covers public package downloads, writes to the PG16 Homebrew Cellar/opt/cache/metadata and service-definition/log paths, matching vector files, and temporary synthetic fixtures. Any necessary dependency action must be separately listed in the frozen plan and authorized before installation.
